# Блогеры в Telegram → РНП Мелори

В личном чате привязанного бота отправьте `/blogger` и нажмите «Добавить блогера».
Форма открывается по `/?miniapp=blogger`. Доступ к каталогу и сохранению возможен только
после проверки подписи Telegram, срока сессии (один час), привязки к профилю и allowed_emails.
Данные всегда сохраняются в исходные products/settings проекта Мелори; Droprise не используется.

Поля интеграции: товар, дата, блогер из базы или новый, формат, ссылка на пост,
стоимость интеграции/доставки/товара, выкуп и его сумма, отзыв и статус, примечание.
Сумма расходов включает выкуп — так же, как существующий расчёт РНП.
Новый блогер получает статус «новый»; имя, соцсети, стоимость поста, оценку и фото-ссылку
можно указать при создании. Совпадающее имя использует существующую карточку.

## Развёртывание

1. Выполнить SQL из раздела «Атомарное добавление интеграции из Telegram» в schema.sql.
   В рабочей базе уже применено как telegram_blogger_atomic_save.
2. Развернуть tg-blogger с verify_jwt=false: собственная авторизация — HMAC Telegram initData.
   Секрет TG_BOT_TOKEN должен совпадать с tg-webhook; остальные переменные Supabase штатные.
   Серверный RPC разрешён только service_role; браузер не получает служебных ключей.
3. Опубликовать frontend на штатном домене Timeweb с VITE_SUPABASE_URL.
4. Затем развернуть обновлённый tg-webhook (с существующим verify_jwt=false).
   Команда /blogger обновляет меню команд при первом обращении; действующая настройка
   вебхука и команды /tasks, создание задач текстом сохраняются.
5. В Telegram проверить существующего и нового блогера, условные поля, запись РНП на
   нужную дату и повторное нажатие. Публикация frontend и обновление webhook выполняются вместе.

## Проверки

`node --test supabase/functions/tg-blogger/auth.test.mjs` (Node 24+)
`npm run build`

Сохранение выполняется одной транзакцией с блокировкой строк и ключом запроса UUID.
Повторный запрос возвращает первый результат. Чужие поля товара и другие записи РНП
сохраняются. Регрессия в рабочей БД проверялась внутри BEGIN/ROLLBACK без сохранения
тестовых товаров или блогеров. Права: anon/authenticated не могут вызывать RPC.
Полный сценарий с настоящим Telegram initData проверяется после публикации frontend.

## Экономия трафика Telegram

Минутная проверка tg-tick загружает только поля уведомлений; файлы, заметки, таблицы
и полная история не передаются. История назначения читается для конкретной задачи
только при появлении нового исполнителя. Запрос /tasks и работа кнопок используют
прежний loadJobs. Состояние tgState сравнивается без учёта порядка ключей JSONB.

Регрессия: `node --test tests/settings-sync.test.mjs tests/tg-tick.test.mjs` после `npm ci`.
Проверки выполняются с подставным HTTP-клиентом и не отправляют сообщения в Telegram.
